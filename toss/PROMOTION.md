# 계산 완료 포인트 프로모션

`intoss://10-eok/promotion`으로 참여한 뒤 직접 계산을 제출하고 정상 결과가 표시되면 포인트 지급을 요청한다. 목표 미도달도 정상 완료다. 저장/공유 결과 열기, 계산 오류, 단순 방문에는 지급하지 않는다. 기본 계산과 추가 분석 광고는 독립이다.

## 현재 상태

- 입력·결과 화면에 포인트 관련 카드를 표시하지 않는다. 성공은 토스 기본 토스트에 맡기고, 실패·확인 필요·참여 불가 상태만 짧은 앱 토스트로 알린다. TEST도 동일하며 지급 기록과 중복 요청 방지는 유지한다. 확정 실패는 사용자가 다시 계산할 때 재시도할 수 있고, 응답 불명은 자동 재시도하지 않는다.

- 기본 OFF. 프로모션 코드와 기간 미설정 시 보상 제안과 SDK 요청이 없다. 이벤트 경로에는 이용 불가 안내를 표시한다.
- 브라우저에서는 실제 지급하지 않는다. 토스 앱 QR 테스트에서 테스트 코드를 사용한다.
- 콘솔 신청/예산 충전/실제 지급/심사 제출은 이 구현에 포함하지 않는다.
- 클라이언트의 지속 기록과 동시 요청 잠금은 연속 계산, 재진입, 통신 응답 유실의 중복 요청을 방지한다. **서버의 사용자별 지급 원장은 없으므로 기기 변경·기록 삭제·변조·동시 웹뷰까지 1인 1회를 보장하지 않는다.** 실제 캠페인 시작 전 콘솔에서 사용자별 지급 한도와 중복 제한을 확인한다. 기간 전체 1회를 플랫폼에서 보장할 수 없다면 서버 원장과 지급 결과 조회를 추가한 뒤 운영한다. 로컬 기록만으로 보장한다고 안내하거나 출시하지 않는다.

## 콘솔 등록안

- 유형: 미션 진행하고 포인트 받기
- 미션 이름: 얼마나 걸릴지 확인하기
- 조건: 이벤트 링크로 진입 후 새 계산의 정상 결과 표시
- 고정 금액: 3원은 제안값. 콘솔에서 등록 가능한 금액과 검수 결과 확인 후 코드와 일치시킨다.
- 이동 URL: `intoss://10-eok/promotion`
- 혜택 탭 노출: 활성화. 공식 안내 위치는 혜택 → 새로운 서비스 써보고이며 사용자별 노출은 다를 수 있다.
- 사용자별 지급 한도와 캠페인 총예산을 설정한다. 10초 구경 상품의 신규 사용자·연령 타기팅이 이 상품에도 적용된다고 가정하지 않는다.

## 테스트 설정

테스트 전용 설정은 Git 제외 파일 `toss/.env.promotion-test.local`에 보관한다. 기본 production 빌드가 이 파일을 자동으로 읽지 않도록 하고, 테스트 빌드를 실행할 때만 환경변수로 전달한다. 테스트 기간은 운영 이벤트 기간과 별개다. 아래 날짜는 예시이므로 갱신한다.

```dotenv
VITE_CALC_PROMOTION_MODE=test
VITE_CALC_PROMOTION_CODE=TEST_콘솔에서발급한코드
VITE_CALC_PROMOTION_AMOUNT=3
VITE_CALC_PROMOTION_START=2026-11-10T00:00:00+09:00
VITE_CALC_PROMOTION_END=2026-11-17T00:00:00+09:00
```

- `test`는 `TEST_` 접두사 코드만, `live`는 접두사 없는 코드만 허용한다. 금액·시작·종료 시각도 필수다.
- 운영 설정은 Git 제외 파일 `toss/.env.production.local`에 둔다. 이 파일은 이후 production 빌드에도 적용된다. 종료 시각은 미포함이므로 종료일 하루 전체를 포함하려면 다음 날 0시(한국 시간)를 지정한다. TEST 빌드는 테스트 환경변수를 명시 주입해 운영 설정을 덮어쓴다.
- 운영에는 승인된 코드, 금액, 기간과 위 사용자별 지급 제한 검증이 필요하다. 테스트 링크 안내에 실제 지급이 없음을 명시한다.
- 승인된 프로모션 내용과 다른 지급 조건으로 코드를 재사용하지 않는다.
- `pnpm release:toss` → 콘솔 테스트 업로드 → QR로 이벤트 경로 실행. 테스트 보상은 실제 포인트가 아니며 비즈월렛이 차감되지 않는다.
- 일반 앱 진입/공유/저장/실패는 미지급, 새 계산/미도달은 지급, 연속 탭/새로고침은 중복 미지급을 실기기에서 확인한다.
- 같은 기기에서 재테스트하려면 TEST 빌드의 `/promotion` 진입 링크에 `testRun=preview-2`처럼 새로운 회차를 넣는다. 영문·숫자·밑줄·하이픈 1~64자만 허용한다. 테스트 모드와 TEST_ 코드가 모두 맞을 때만 기록을 별도 보관하며 기존 기록을 삭제하지 않는다. 같은 회차 재진입은 중복 요청하지 않고, 운영 코드에서는 이 쿼리를 무시한다. 새 회차 진입만으로 요청하지 않으며 직접 계산을 완료해야 한다.

## 실패와 복구

SDK 3.8.1의 `Promotion.grantReward`와 `User.getAnonymousKey`를 사용한다. 저장소 읽기 실패를 '신규 참여'로 취급하지 않는다. 요청 전에 pending을 기록하고 SDK가 nonempty key를 반환한 경우에만 지급 완료로 표시한다.

확인된 `4110` 실패만 사용자가 명시적으로 재요청할 수 있다. 타임아웃, 알 수 없는 오류, 요청 중 앱 종료는 지급 여부 불명 상태로 남겨 재호출하지 않는다. 토스 적립 내역과 문의 경로를 안내하며, 운영자가 지급 기록을 대조하기 전 로컬 pending을 지우지 않는다. 영구 저장 실패 후에도 pending을 유지한다. 지급 결과 키·익명 식별자는 Analytics에 보내지 않는다.
